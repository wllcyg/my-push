## 模块与 import

**一个 `.py` 文件就是一个模块。**

```python
# utils.py
PI = 3.14159

def add(a, b):
    return a + b

class Counter:
    ...
```

```python
# main.py
import utils                          # 导入整个模块
print(utils.add(1, 2))

from utils import add, PI             # 导入具体名称
print(add(1, 2))

from utils import add as plus         # 起别名
import numpy as np                    # 常见的约定别名

# ❌ 不要用通配符导入，会污染命名空间，且看不出名称来源
# from utils import *
```

### 标准库、第三方库、自己的模块

```python
# 推荐的导入顺序，三组之间空一行（PEP 8，isort / ruff 可自动整理）
import json                           # 1. 标准库
import os
from pathlib import Path

import httpx                          # 2. 第三方库
from fastapi import FastAPI

from modules.core.database import get_db     # 3. 项目内部模块
```

### 模块只会被执行一次

第一次 `import` 时 Python 会执行整个文件，之后结果缓存在 `sys.modules`，再次 import 直接复用。
因此模块里的顶层代码（如创建数据库引擎）只会运行一次，天然就是单例。

```python
# config.py
print("config 被加载了")               # 只会打印一次，无论被多少文件 import
settings = {"debug": True}
```

## 包与 `__init__.py`

**包含 `__init__.py` 的目录就是一个包**（3.3+ 没有它也能当"命名空间包"用，
但建议显式写上，行为更可预期）。

```
myapp/
├── __init__.py
├── main.py
├── core/
│   ├── __init__.py
│   └── database.py
└── user/
    ├── __init__.py
    ├── user_entity.py
    └── user_service.py
```

```python
# 绝对导入（推荐）：从项目根开始写完整路径
from myapp.core.database import get_db
from myapp.user.user_service import UserService

# 相对导入：用点号表示相对位置，只能在包内部使用
# 在 myapp/user/user_service.py 中：
from . import user_entity              # 同目录
from .user_entity import User          # 同目录的模块
from ..core.database import get_db     # 上一级目录
```

### `__init__.py` 的用途

```python
# myapp/user/__init__.py
# 1. 可以是空文件，只表示"这是一个包"
# 2. 也可以对外暴露接口，简化导入路径：
from .user_service import UserService
from .user_entity import User

__all__ = ["UserService", "User"]      # 控制 from myapp.user import * 导出什么

# 之后外部可以直接写：
# from myapp.user import UserService
```

不要在 `__init__.py` 里堆太多逻辑，容易造成**循环导入**。

### 循环导入

```python
# a.py
from b import func_b      # b 还没执行完就又 import a
def func_a(): ...

# b.py
from a import func_a      # ❌ ImportError: cannot import name (most likely due to a circular import)
def func_b(): ...
```

解决思路：

1. 把共用部分抽到第三个模块。
2. 把 import 挪到函数内部（延迟导入）。
3. 仅用于类型注解时，用 `TYPE_CHECKING`：

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:                       # 运行时不会执行，只给类型检查器看
    from myapp.user.user_entity import User

def show(user: "User") -> None: ...    # 注解写成字符串
```

## `if __name__ == "__main__"`

```python
# tool.py
def main():
    print("作为脚本运行")

if __name__ == "__main__":
    main()
```

- `python tool.py`：`__name__` 是 `"__main__"`，会执行 `main()`。
- 被别的文件 `import tool`：`__name__` 是 `"tool"`，**不会**执行 `main()`。

这样同一个文件既能被导入复用，又能直接运行调试，类似 Node 里的 `require.main === module`。

### 作为模块运行

```bash
python -m myapp.main        # 以包的方式运行，相对导入才能正常工作
```

直接 `python myapp/user/user_service.py` 运行包内文件，相对导入会报错
`attempted relative import with no known parent package`，改用 `python -m` 即可。

## import 查找机制与常见报错

Python 按顺序在这些位置找模块：

1. 已缓存的 `sys.modules`
2. 内置模块
3. `sys.path` 里的目录：脚本所在目录、`PYTHONPATH`、虚拟环境的 `site-packages`

```python
import sys
print(sys.path)
```

常见报错：

| 报错 | 常见原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: No module named 'xxx'` | 没安装，或装在别的 Python 环境里 | 确认用的是项目虚拟环境，`uv add xxx` |
| `ModuleNotFoundError: No module named 'modules'` | 运行位置不对，项目根不在 `sys.path` | 在项目根目录运行，用 `uv run` / `python -m` |
| `ImportError: cannot import name` | 循环导入或名称拼错 | 见上文循环导入 |
| 自己文件名和库同名 | 如建了 `json.py`、`random.py`，会遮蔽标准库 | 重命名自己的文件 |
| 相对导入报错 | 把包内文件当脚本直接运行 | `python -m 包名.模块名` |

## 文件与路径操作（pathlib）

现代 Python 用 `pathlib.Path` 代替 `os.path`，写法更直观。

```python
from pathlib import Path

p = Path("data") / "users" / "alice.json"    # 用 / 拼接路径，自动处理 Windows/Linux 分隔符

print(p.name)          # alice.json
print(p.stem)          # alice
print(p.suffix)        # .json
print(p.parent)        # data/users
print(p.exists(), p.is_file(), p.is_dir())

# 当前文件所在目录，常用来定位项目资源，避免依赖"从哪里运行"
BASE_DIR = Path(__file__).resolve().parent

# 创建目录
(BASE_DIR / "logs").mkdir(parents=True, exist_ok=True)

# 遍历
for f in BASE_DIR.glob("*.py"):              # 当前目录
    print(f)
for f in BASE_DIR.rglob("*.md"):             # 递归
    print(f)

# 家目录
Path.home()
```

### 读写文本文件

```python
p = Path("notes.txt")

p.write_text("你好\n第二行", encoding="utf-8")    # 一次写入
text = p.read_text(encoding="utf-8")              # 一次读取
lines = text.splitlines()

# 需要逐行或追加时用 open + with（保证文件一定会被关闭）
with open("notes.txt", "a", encoding="utf-8") as f:
    f.write("\n追加一行")

with open("notes.txt", encoding="utf-8") as f:
    for line in f:                                # 逐行读取，大文件也不占内存
        print(line.rstrip())
```

**务必写 `encoding="utf-8"`**，否则在 Windows 上默认编码是 GBK，中文文件会乱码或报错。

常用的 open 模式：`"r"` 读（默认）、`"w"` 覆盖写、`"a"` 追加、`"rb"` / `"wb"` 二进制。

### 复制、移动、删除

```python
import shutil
from pathlib import Path

shutil.copy("a.txt", "b.txt")
shutil.move("b.txt", "backup/b.txt")
shutil.rmtree("old_dir")                  # 递归删除整个目录，慎用
Path("tmp.txt").unlink(missing_ok=True)   # 删除文件
```

## 读写 JSON / CSV / 文本

### JSON

```python
import json
from pathlib import Path

data = {"name": "张三", "tags": ["a", "b"]}

# 写
Path("user.json").write_text(
    json.dumps(data, ensure_ascii=False, indent=2),
    encoding="utf-8",
)

# 读
data = json.loads(Path("user.json").read_text(encoding="utf-8"))

# 也可以直接用文件对象
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
with open("user.json", encoding="utf-8") as f:
    data = json.load(f)
```

`dumps` / `loads` 处理字符串（s = string），`dump` / `load` 处理文件对象。

JSON 不认识 `datetime`、`Decimal`、自定义对象，直接序列化会报 `TypeError`：

```python
from datetime import datetime
json.dumps({"t": datetime.now()}, default=str)    # default 指定兜底转换函数
```

### CSV

```python
import csv

with open("scores.csv", "w", newline="", encoding="utf-8-sig") as f:   # utf-8-sig 让 Excel 打开不乱码
    writer = csv.DictWriter(f, fieldnames=["name", "score"])
    writer.writeheader()
    writer.writerow({"name": "Alice", "score": 90})

with open("scores.csv", newline="", encoding="utf-8-sig") as f:
    for row in csv.DictReader(f):
        print(row["name"], int(row["score"]))
```

## 环境变量与 .env

配置（数据库密码、API Key）不要写死在代码里，也不要提交到 Git。

```python
import os

host = os.environ.get("DB_HOST", "localhost")        # 带默认值
port = int(os.environ.get("DB_PORT", "3306"))        # 环境变量永远是字符串，要自己转类型
secret = os.environ["API_KEY"]                       # 必须存在，缺失时 KeyError
```

用 `.env` 文件管理本地开发配置：

```ini
# .env（加入 .gitignore，绝对不要提交）
DB_HOST=localhost
DB_PORT=3306
DB_PASSWORD=your_password
```

```python
from dotenv import load_dotenv        # uv add python-dotenv
load_dotenv()                          # 读取 .env，写入 os.environ
```

更推荐的做法是上一章讲的 `pydantic-settings`，自动读取并转换类型。
同时提交一份 `.env.example`（只有变量名，没有真实值）告诉别人要配哪些变量。

## uv：现代 Python 项目管理

**uv** 是 Astral 公司用 Rust 写的工具，一个命令同时替代 `pip`、`venv`、`pip-tools`、
`pyenv`、`poetry` 的大部分功能，速度比 pip 快一个数量级。`two/project` 里有 `uv.lock`，
说明你的项目已经在用它了。

### 安装

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 或者用 pip / brew
pip install uv
brew install uv

uv --version
```

### 日常命令（对应 npm / pnpm）

```bash
# 新建项目（生成 pyproject.toml、.python-version、main.py）
uv init my-app
cd my-app

# 添加依赖（自动创建 .venv、写入 pyproject.toml、更新 uv.lock）
uv add fastapi "uvicorn[standard]" sqlalchemy

# 添加开发依赖
uv add --dev pytest ruff pyright

# 移除依赖
uv remove httpx

# 按 lock 文件安装全部依赖（新同事 clone 项目后第一件事）
uv sync

# 在项目虚拟环境中运行命令，不需要手动激活 venv
uv run python main.py
uv run uvicorn main:app --reload
uv run pytest

# 查看依赖树
uv tree

# 升级依赖
uv lock --upgrade-package fastapi
uv sync
```

### 管理 Python 版本

```bash
uv python list                # 查看可用版本
uv python install 3.12        # 安装指定版本
uv python pin 3.12            # 写入 .python-version，让本项目固定使用该版本
```

不再需要 pyenv，也不用担心系统自带的 Python 版本不对。

### 运行单文件脚本

```bash
uv run script.py
uv run --with requests script.py          # 临时带上某个依赖，不污染项目
```

### 对接老项目（requirements.txt）

```bash
uv pip install -r requirements.txt        # 兼容 pip 的接口
uv add -r requirements.txt                # 把 requirements 导入到 pyproject.toml
uv pip freeze > requirements.txt          # 导出（部署到只认 requirements 的环境时用）
```

### 国内镜像

```toml
# pyproject.toml 中添加
[[tool.uv.index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true
```

或设置环境变量 `UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple`。

### 虚拟环境的作用

虚拟环境（`.venv/`）让每个项目拥有独立的依赖，互不冲突，和每个 Node 项目有自己的
`node_modules` 一个道理。**`.venv/` 不要提交到 Git**，只提交 `pyproject.toml` 和 `uv.lock`。

## pyproject.toml

项目的"身份证 + 依赖清单"，相当于 `package.json`。

```toml
[project]
name = "aftersales-api"
version = "0.1.0"
description = "汽车售后服务管理系统后端"
requires-python = ">=3.12"
dependencies = [
    "fastapi>=0.115",
    "uvicorn[standard]>=0.30",
    "sqlalchemy[asyncio]>=2.0",
    "asyncmy>=0.2.9",
    "alembic>=1.13",
    "pydantic-settings>=2.4",
]

[dependency-groups]
dev = [
    "pytest>=8.0",
    "pytest-asyncio>=0.24",
    "ruff>=0.6",
    "pyright>=1.1",
]

[tool.ruff]
line-length = 100

[tool.pytest.ini_options]
asyncio_mode = "auto"
asyncio_default_fixture_loop_scope = "function"
testpaths = ["tests"]
```

- `uv.lock`：锁定所有依赖（含间接依赖）的精确版本，等价于 `pnpm-lock.yaml`，**要提交**。
- `ruff`：同时替代 flake8、isort、black 的代码检查与格式化工具，命令 `uv run ruff check .` 与
  `uv run ruff format .`。

## 推荐的项目结构

按业务模块分层，和你熟悉的 NestJS 结构对应（`two/project` 也是这个思路）：

```
aftersales-api/
├── pyproject.toml
├── uv.lock
├── .python-version
├── .env                    # 本地配置，不提交
├── .env.example            # 配置模板，提交
├── .gitignore
├── alembic.ini
├── alembic/                # 数据库迁移
├── main.py                 # FastAPI 入口
├── modules/
│   ├── core/               # database.py、response.py、logger.py 等公共能力
│   ├── config/             # settings.py
│   ├── customer/
│   │   ├── customer_entity.py       # ORM 模型        ≈ NestJS Entity
│   │   ├── customer_dto.py          # Pydantic 模型   ≈ DTO
│   │   ├── customer_service.py      # 业务逻辑        ≈ Service
│   │   └── customer_controller.py   # 路由            ≈ Controller
│   ├── vehicle/
│   └── work_order/
└── tests/
```

`.gitignore` 至少包含：

```gitignore
.venv/
__pycache__/
*.pyc
.env
.pytest_cache/
.ruff_cache/
```

> 你的 `my-push` 仓库里提交了大量 `__pycache__/*.pyc`，把上面这几行加进 `.gitignore`，
> 再执行 `git rm -r --cached --ignore-unmatch '**/__pycache__'` 就能把它们从版本库里清掉（本地文件保留）。

## 和 Node.js / npm 对照

| 需求 | Node 生态 | Python 生态 |
|---|---|---|
| 版本管理 | nvm / fnm | `uv python install` / pyenv |
| 包管理器 | npm / pnpm | **uv**（pip） |
| 项目清单 | `package.json` | `pyproject.toml` |
| 锁文件 | `pnpm-lock.yaml` | `uv.lock` |
| 依赖目录 | `node_modules` | `.venv` |
| 安装依赖 | `pnpm install` | `uv sync` |
| 添加依赖 | `pnpm add x` | `uv add x` |
| 运行脚本 | `pnpm run dev` | `uv run ...` |
| 一次性执行 | `npx xxx` | `uvx xxx`（如 `uvx ruff check .`） |
| 导入 | `import x from './x'` | `from pkg.x import y` |
| 入口守卫 | `require.main === module` | `if __name__ == "__main__"` |
| 代码检查 | eslint + prettier | ruff |
| 类型检查 | tsc | pyright / mypy |
| 配置文件 | dotenv | python-dotenv / pydantic-settings |
