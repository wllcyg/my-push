# Python Agent 框架深度对比调研简报

> LangGraph · AutoGen · CrewAI — 核心架构、适用场景与优缺点全景分析
>
> 生成日期：2025 年 6 月 | 版本：v1.0

---

## 执行摘要

当前 Python Agent 领域已形成三大主流框架并立的格局：

| 框架 | 核心隐喻 | 一句话定位 |
|------|----------|------------|
| **LangGraph** | 流程图 / 状态机 | 精密的"生产级 Agent 运行时"，以图结构和状态持久化为核心 |
| **AutoGen** | 群聊 / 会议 | 灵活的"多智能体对话引擎"，以 Agent 间对话协作为核心 |
| **CrewAI** | 职场团队 | 轻量的"角色编排框架"，以 Role-playing 和低学习门槛为核心 |

三者各有侧重，并非互斥关系，而是服务于不同层次的开发需求。本文从核心架构、适用场景、优缺点三个维度进行系统对比，并提供选型决策参考。

## 二、核心架构设计对比

### 2.1 架构哲学

| 维度 | LangGraph | AutoGen | CrewAI |
|------|-----------|---------|--------|
| **核心抽象** | 有向图（Directed Graph） | 多 Agent 对话（Multi-Agent Conversation） | 角色团队（Role-based Crew） |
| **控制范式** | **显式控制**：开发者精确定义节点和边 | **对话涌现**：Agent 自主协作对话 | **角色驱动**：预设角色与任务流程 |
| **执行模型** | 状态机驱动，支持循环、分支、暂停 | 对话轮次驱动，支持动态发言调度 | 任务链驱动，顺序或分层执行 |
| **抽象层级** | 低层级编排（接近"汇编"） | 中高层编排（接近"对话管理"） | 高层编排（接近"自然语言配置"） |

### 2.2 LangGraph 架构：StateGraph + Checkpoint

LangGraph 将 AI 应用建模为**有状态的有向图**，核心组件包括：

- **State（状态）**：贯穿全局的共享数据容器，使用 `TypedDict` / Pydantic 定义，通过 Reducer 控制合并策略
- **Node（节点）**：计算单元，接收 State 输入，返回状态增量更新
- **Edge（边）**：普通边（固定路径）和条件边（动态路由），支持循环和分支
- **Checkpoint（检查点）**：每步自动持久化状态快照，支持断点续传和时间旅行
- **编译执行**：`graph.compile()` 将图定义转换为可执行对象

```
StateGraph 架构示意：
  ┌──────┐     ┌──────────┐     ┌──────────┐
  │START │────→│  Node A  │────→│  Node B  │
  └──────┘     └────┬─────┘     └────┬─────┘
                    │ 条件路由        │
               ┌────┴────┐      ┌────┴────┐
               │  Route  │      │  END    │
               └─────────┘      └─────────┘
                    ↕ 循环 ↕
               状态在节点间流转、更新、持久化
```

### 2.3 AutoGen 架构：分层消息传递（v0.4）

AutoGen v0.4 采用清晰的**三层架构**：

- **autogen-core（核心层）**：异步消息传递基础设施、Agent 运行时环境、事件驱动架构
- **autogen-agentchat（应用层）**：预构建的 Agent（AssistantAgent）和 Team（RoundRobin/Selector GroupChat）
- **autogen-ext（扩展层）**：可插拔的模型客户端、工具、Docker 代码执行器

```
AutoGen v0.4 分层架构：
  ┌─────────────────────────────────────┐
  │    autogen-agentchat (应用层)        │
  │    AssistantAgent / Teams            │
  ├─────────────────────────────────────┤
  │    autogen-core (核心层)             │
  │    异步消息 / 事件驱动 / Agent Runtime│
  ├─────────────────────────────────────┤
  │    autogen-ext (扩展层)              │
  │    OpenAI / Docker / 工具集成        │
  └─────────────────────────────────────┘
```

### 2.4 CrewAI 架构：双模式设计（Crews + Flows）

CrewAI 最新版本引入**双模式架构**：

- **Crews 模式**：角色协作模式，Agent → Crew → Task → Process，优化自主性与协作智能
- **Flows 模式**：事件驱动模式，通过 `@start`、`@listen`、`@router` 装饰器实现精确任务编排

```
CrewAI Crews 模式示意：
  Crew (团队容器)
   ├── Agent 1 (研究员) ──→ Task 1 (数据搜集)
   ├── Agent 2 (分析师) ──→ Task 2 (趋势分析)
   └── Agent 3 (写作者) ──→ Task 3 (报告撰写)
   
   流程：Sequential（顺序） 或 Hierarchical（分层委派）
```

### 2.5 状态管理机制对比

| 能力 | LangGraph | AutoGen | CrewAI |
|------|-----------|---------|--------|
| **状态管理** | 中央状态对象，全局可见可追踪 | 分布式对话历史，各 Agent 自维护 | 链式传递，Task 输出自动流转 |
| **持久化** | ✅ 内置 Checkpointing，每步自动保存 | ❌ 无内置持久化，需自行实现 | ⚠️ 支持任务输出保存和 Memory 模块 |
| **状态回溯** | ✅ Time Travel，回溯到任意历史状态 | ❌ 不支持 | ❌ 不支持 |
| **跨会话记忆** | ✅ Store 机制，支持语义查询 | ⚠️ v0.4 引入 Memory 概念 | ⚠️ 内置 Memory 模块 |
| **断点续传** | ✅ 从任意检查点恢复执行 | ❌ 不支持 | ❌ 不支持 |
| **会话隔离** | ✅ Thread 机制，天然隔离 | ⚠️ 需自行管理 | ⚠️ 需自行管理 |

**结论**：LangGraph 在状态管理上具有压倒性优势，这是其作为"生产级运行时"的核心竞争力。AutoGen 和 CrewAI 的状态管理更轻量化，但牺牲了持久化和回溯能力。

## 三、多 Agent 协作方式对比

| 维度 | LangGraph | AutoGen | CrewAI |
|------|-----------|---------|--------|
| **协作机制** | 通过多节点/子图实现 | 对话驱动（PairChat/GroupChat/Nested） | 角色驱动（Sequential/Hierarchical） |
| **Agent 角色定义** | 节点函数 + 系统提示词 | Agent 类型 + 系统提示词 | Role/Goal/Backstory 三元组 |
| **发言调度** | 条件边动态路由 | GroupChatManager 多种策略 | 预定义流程或 Manager 委派 |
| **Agent 间通信** | 共享 State 对象 | 消息传递（对话历史） | Task 输出链式传递 |
| **嵌套协作** | ✅ 子图（Subgraph）机制 | ✅ Nested Chat 机制 | ✅ Hierarchical 流程中的委派 |
| **代码执行** | ❌ 需自行集成 | ✅ 内置 Docker 沙箱 | ❌ 需借助工具集成 |
| **人机协作** | ✅ interrupt 机制 + 检查点持久化 | ✅ UserProxyAgent 三档配置 | ⚠️ 基础支持 |

**关键差异解读**：

- **LangGraph 的"显式控制"**：开发者像画流程图一样定义整个工作流，每个节点做什么、何时跳转、如何分支都由代码精确控制。适合需要**确定性、可审计、可恢复**的生产场景。
- **AutoGen 的"对话涌现"**：开发者定义 Agent 角色和对话规则，具体协作过程由 LLM 驱动，Agent 之间可以辩论、纠错、迭代。适合需要**灵活性、创造性、多角色协作**的探索场景。
- **CrewAI 的"角色编排"**：开发者定义角色、目标和背景故事，框架自动编排任务执行流程。适合需要**快速搭建、低门槛**的内容生成和研究分析场景。

## 四、适用场景对比

### 4.1 LangGraph 最适合的场景

| 场景 | 原因 |
|------|------|
| **生产级 Agent 系统** | 检查点 + 断点续传 + 容错，确保系统可靠性 |
| **长时运行工作流** | 状态持久化支持跨小时/天/周的流程 |
| **需要审计追踪的系统** | 完整的状态变更历史，满足合规要求 |
| **复杂条件逻辑工作流** | 图结构天然支持复杂分支、循环、并行 |
| **需要人工审批的流程** | 中断/恢复 + 状态保持 |
| **RAG 增强应用** | 多步检索-推理-验证的复杂流程 |

**代表企业用户**：LinkedIn、Uber、Klarna、GitLab

### 4.2 AutoGen 最适合的场景

| 场景 | 原因 |
|------|------|
| **多角色协作任务** | 群聊模式天然支持多专家角色协作 |
| **代码生成与数据分析** | 内置代码执行 + 生成-执行-反馈循环 |
| **快速原型开发** | 对话驱动，配置简单，上手快 |
| **创意/探索性任务** | Agent 间辩论、纠错，适合开放性任务 |
| **软件开发模拟** | 产品经理→架构师→工程师→审查员的角色链 |
| **需要代码沙箱的场景** | Docker 隔离执行，安全可控 |

### 4.3 CrewAI 最适合的场景

| 场景 | 原因 |
|------|------|
| **内容生成** | "研究 → 撰写 → 编辑"的完整协作流水线 |
| **研究分析** | 多 Agent 分工完成信息搜集、数据分析和报告撰写 |
| **旅行规划** | 不同 Agent 分别负责目的地调研、行程安排、预算计算 |
| **金融分析** | 多 Agent 协作完成市场数据收集、趋势分析和投资建议 |
| **自动化工作流** | 如邮件处理、电商自动化等 |
| **非技术用户使用** | API 简洁，学习门槛低 |

## 五、优缺点系统对比

### 5.1 LangGraph

| ✅ 优势 | ❌ 劣势 |
|---------|---------|
| 精细的流程控制（图结构） | 学习曲线陡峭，概念多（State/Node/Edge/Checkpoint） |
| 强大的状态持久化与检查点 | 简单场景过度设计 |
| 断点续传与容错能力 | 调试复杂度较高（循环 + 条件分支） |
| Time Travel 回溯能力 | 持久化带来性能开销（尤其 sync 模式） |
| 生产就绪（企业验证） | API 变化频繁，需持续跟进 |
| 完整的生态工具链（LangSmith/Studio） | 依赖 LangChain 生态 |
| 商业化支持（LangGraph Platform） | 多 Agent 对话不如 AutoGen 直观 |

### 5.2 AutoGen

| ✅ 优势 | ❌ 劣势 |
|---------|---------|
| 对话驱动，直观易懂 | v0.2 到 v0.4 不向后兼容（完全重写） |
| 内置 Docker 代码执行能力 | 无内置状态持久化 |
| 灵活的多角色协作 | 多轮对话 LLM 调用成本高 |
| 快速原型开发 | 复杂流程控制不如 LangGraph |
| 渐进式人机协作（三档 human_input_mode） | 安全性需仔细设计 |
| 微软背书，社区活跃 | 生产级部署案例较少 |
| 跨语言支持（Python + .NET） | 上下文窗口管理需自行处理 |

### 5.3 CrewAI

| ✅ 优势 | ❌ 劣势 |
|---------|---------|
| API 简洁、极易上手 | 灵活性受限，牺牲了 Agent 间的"生动互动" |
| 学习曲线低，适合初学者 | 大规模编排能力有限 |
| 角色定义直观（Role/Goal/Backstory） | 深度定制受限 |
| 最新版本已脱离 LangChain 独立重写，性能优化 | 与 LangGraph 等相比，状态机控制较弱 |
| 内置记忆和委派能力 | 上下文窗口溢出风险需注意 |
| CrewAI Enterprise 企业级支持 | 社区生态和文档仍在发展中 |

## 八、混合使用方案

三个框架并非互斥，可以组合使用以发挥各自优势：

### 方案一：LangGraph + AutoGen

```
┌─────────────────────────────────────────────┐
│            LangGraph（顶层编排）               │
│                                              │
│  [Node A] ──→ [Node B] ──→ [Node C] ──→ END │
│                  │                           │
│                  ▼                           │
│          ┌──────────────┐                    │
│          │  AutoGen      │                    │
│          │  GroupChat    │                    │
│          │  (子图节点)    │                    │
│          │  Agent1↔Agent2│                    │
│          └──────────────┘                    │
└─────────────────────────────────────────────┘
```

- **LangGraph** 负责：整体流程编排、状态持久化、错误恢复、人机审批
- **AutoGen** 负责：特定节点内的多 Agent 对话协作、代码生成与执行

### 方案二：LangGraph + CrewAI

```
┌─────────────────────────────────────────────┐
│            LangGraph（流程骨架）              │
│                                              │
│  [数据获取] ──→ [CrewAI Crew] ──→ [审核]    │
│                      │                       │
│                      ▼                       │
│              研究员Agent → 分析师Agent        │
│                   → 写作者Agent               │
└─────────────────────────────────────────────┘
```

- **LangGraph** 负责：长流程编排、状态管理、人工审核节点
- **CrewAI** 负责：内容生成流水线（研究→分析→撰写）
